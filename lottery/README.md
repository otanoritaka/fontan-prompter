# 学会抽選システム（海南島会場用）

QRコード登録 → 番号を画面表示＋メール → ホストがランダム抽選
（1ラウンド = 術者5名 + 助手5名 × 4ラウンド = 計40名）

- Google・海外CDN・外部フォントを一切使わないため、**中国の携帯回線から利用可能**
- 参加者画面は英語、ホスト画面はスクリーン投影用
- 一度当選した人は以降のラウンドから自動除外
- 不在者は「Absent → redraw」で同じ役割の代替者を再抽選
- 抽選は暗号論的乱数（`crypto.randomInt`）でサーバー側にて実施・記録

## 起動

```bash
cd lottery
npm install
ADMIN_KEY=好きな合言葉 EVENT_NAME="Hainan Lucky Draw" npm start
```

起動するとコンソールに以下が表示されます。

- 登録ページURL（QRコードの中身）
- ホスト画面URL：`/host?key=合言葉`

ホスト画面の「QR code」タブを開くとQRコードが大きく表示されるので、会場スクリーンに映すかスライドに貼ってください。

## 設定（環境変数）

| 変数 | 内容 | 既定値 |
|---|---|---|
| `ADMIN_KEY` | ホスト画面の合言葉 | 起動時にランダム生成 |
| `EVENT_NAME` | 画面・メールに出る名前 | `Lucky Draw` |
| `PUBLIC_URL` | QRコードに入れる公開URL（例 `https://draw.example.com`） | アクセス中のURL |
| `PORT` | ポート | `3000` |
| `ROUNDS` / `PER_ROLE` | ラウンド数 / 1役割あたりの人数 | `4` / `5` |
| `SMTP_HOST` `SMTP_PORT` `SMTP_SECURE` `SMTP_USER` `SMTP_PASS` `MAIL_FROM` | メール送信設定（未設定ならメールなし・画面表示のみ） | — |

## 運用パターン

### A. クラウド（香港／シンガポール）
- Alibaba Cloud 香港リージョン等の小さなサーバーで起動（中国本土サーバーはICP備案が必要なので避ける）
- `PUBLIC_URL` を設定してQRコードを作る
- **事前に中国の携帯回線から実際にアクセスできるか必ず確認**

### B. 会場オフライン（最も確実）
- ホストPC＋持ち込みWi-Fiルーターで閉じたネットワークを作る
- 参加者はそのWi-Fiに接続 → QRを読む（URLは `http://192.168.x.x:3000/`）
- メールは不要、または後から登録者一覧の「Resend」で送信

### メールについて（中国向け）
- 中国の参加者は QQメール／163メールが多く、海外SMTPからは迷惑メール扱い・遅延が起きやすい
- **番号の正式な通知は登録完了画面（スクリーンショットを依頼）**とし、メールは控え扱い
- 送るなら Alibaba Cloud DirectMail（香港/シンガポール）や 163/QQ企業メールのSMTPが届きやすい

### 注意
- **微信（WeChat）のスキャンで開くと、知らないドメインは警告・ブロックされることがあります。** QRはスマホ標準のカメラで読むよう案内してください（オフライン方式のIPアドレスURLでも同様）
- 個人情報（中国PIPL）に配慮し、登録画面に利用目的を記載すること、イベント後に `data/db.json` を削除することを推奨

## データ
- 登録者・抽選結果は `data/db.json` に保存（サーバー再起動しても保持）
- ホスト画面「Registrants」タブからCSVダウンロード可（Excelで文字化けしないBOM付き）
- 全リセット：サーバー停止後 `data/` フォルダを削除
